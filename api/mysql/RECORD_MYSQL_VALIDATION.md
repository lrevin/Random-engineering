# 학습 기록·기본 문제 MySQL 전환 검증

2026-11-07 · 로컬 작업 · MySQL 8.0.46 · 기존 19개 테이블 사용

## 반영 위치

- `api/mysql/record-service.mjs`, `record-http.mjs`: 기록·답안·오답·메모·XP·동기화
- `api/mysql/question-service.mjs`: 기존 MySQL 문제 조회 로직을 이 폴더로 이동
- `api/server/`: 실행 경로 연결, 업로드 크기 제한 분리, 테스트 명령 추가
- `api/mysql/app-integration/app/src/`: 타입·클라이언트·동기화·퀴즈·기록 화면 전환 후보

기존 `app/`, `api/supabase/`, `api/quiz-server/`는 변경하지 않았다. 이번 검토 후 develop에만 공유한다.

## 실제 검증

- 신규 통합 테스트 13개 통과: 저장·7개 답안 보존·본인 접근·XP 계산·중복/동시 요청·부분 실패·메모 충돌·삭제/재전송·커서·롤백·시간 정책·기본 문제 조회
- 전환 후보의 실제 클라이언트로 MySQL API에 접속하여 오프라인 메모 반영·충돌·다른 기기의 삭제·이전 불완전 기록 보관·계정 변경 중 응답 무시 확인
- 기존 인증 14개·프로필/탈퇴 9개·DB 8개·기본 회귀 6개 모두 통과
- 전환 후보를 최신 앱 복사본에 적용하여 타입 검사·lint·MySQL 설정 웹 빌드 확인
- 생성한 테스트 사용자와 관련 데이터는 테스트 종료 후 정리

초기 테스트에서 MySQL COUNT 반환값을 숫자로 가정한 테스트 오류와 기록 화면 JSX 문법 오류를 발견해 수정한 후 재검증했다.

## 남은 범위

앱이 제공한 문제 스냅샷은 client_reported로 처리한다. 서버 출제 기반 server_verified 채점·AI 문제 MySQL 직접 수신·기존 Supabase 데이터 이전은 미구현이다. 전체 스냅샷 조회의 대규모 최적화, 90일 삭제 표식 정리 자동화, 삭제된 기록의 로컬 메모 초안 복구 화면과 실기기 검증도 남아 있다. 기존 답안이 없는 기록은 전체 답안을 만들어내지 않고 기기에만 보관한다.

실제 앱 파일에 병합하기 전까지 현재 앱의 실행 방식은 바뀌지 않는다.

## 2026-11-08 Supabase 대비 재검토

회원 탈퇴·프로필·학습 기록·기본 문제의 기존 Supabase 호출·스키마와 MySQL API·전환 후보를 대조했다. 본인 데이터 접근 제한, 프로필 필드, 기록·오답 조회와 기본 문제 조회가 대응한다. 탈퇴의 7일 유예, 전체 답안 필수 저장, XP 서버 계산은 V2 정책에 따른 의도된 변경이다. 기존 요약 기록의 자동 변환과 실제 앱 병합은 포함하지 않는다.

동기화 중 삭제한 기록이 다시 표시될 수 있는 경합을 수정하여 조회·업로드·삭제를 같은 순서 대기열에서 처리했다. 삭제된 기록의 초안을 보관하는 동안 다른 기록에 새로 작성한 메모도 최신 값을 사용하도록 수정했다. 실제 MySQL API와 후보 클라이언트를 연결한 회귀 사례를 추가했으며 전체 테스트 50개, 타입 검사·lint·웹 빌드를 통과했다. 기존 app·Supabase·AI 서버 파일은 유지한다.
