# MySQL 프로필·회원 탈퇴 검증

검증일: 2026-11-07. 로컬 feature/mysql-auth에서만 수정했으며 커밋·push하지 않았다. 기존 app/·Supabase·SQL 테이블 구조는 변경하지 않았다. 앱 연결은 api/mysql/app-integration/app 후보 파일에만 반영했다.

## 구현

- GET/PUT /me/profile: 본인 프로필 조회·생성·수정, 관심 분야 존재·중복·닉네임·난이도·학습 시간·알림 설정 검사.
- DELETE /me: deleting 전환·신청 시각·모든 세션 폐기·auth_version 증가를 트랜잭션으로 처리. 202와 7일 뒤 삭제 예정 시각 반환.
- POST /auth/cancel-deletion: 이메일·비밀번호 확인 후 7일 이내 취소. 이전 토큰은 부활하지 않으며 새 로그인 필요.
- accounts:purge: 기간 만료를 잠금 안에서 재검사하고 기록·답안·XP·세션·프로필 등 소유 데이터를 순서대로 삭제. 정리 스케줄 자체는 미설정.
- 전환 앱: 프로필 서버 저장·로그인 시 조회, 탈퇴 신청·로그인 화면 취소, 탈퇴 성공 시 기기 로그인·학습 데이터 정리. 기존 Supabase 분기는 유지.

## 실제 MySQL 테스트

MySQL 8.0.46에서 신규 테스트 9개(상위 1 + 세부 8), 기존 인증 14개·DB 8개·회귀 6개 통과.

1. 비인증 프로필 접근 거절·미등록 404.
2. 프로필 생성·수정·왕복 조회·다른 사용자 ID 주입 방지.
3. 잘못된 입력 거절과 기존 프로필 보존.
4. 탈퇴 신청과 모든 세션·이전 Access Token 즉시 차단, 타 계정 보존.
5. 비밀번호 확인 취소·프로필 보존·이전 토큰 재사용 차단.
6. 7일 전 정리 제외·기간 경과 취소 거절.
7. 정리 실패 롤백과 정상 실행 시 참조 데이터 삭제·중복 정리 안전성.
8. 실제 앱 인증 클라이언트의 프로필·탈퇴·취소 API 연결.

테스트 계정은 종료 시 삭제한다. 기본 문제 데이터는 유지한다. API 테스트는 완성된 React 화면의 실기기 조작 검증을 대신하지 않는다. 별도 검증용 앱에 전환 후보를 합쳐 타입·코드 검사와 웹 빌드를 수행하며, 기존 앱 소스는 그대로 둔다.

## 남은 범위

학습 기록·XP·동기화 API, 소셜 계정 탈퇴 취소, 운영 정리 스케줄, 실제 기기 검증은 후속 작업이다. 기존 Supabase 계정·데이터를 자동 이관하지 않는다.
