# 뽑공 실시간 퀴즈 생성 서버 API (EC2 API 서버 → 강의실 PC)

강의실 PC의 서버는 PC 안(127.0.0.1:8788)에서만 열리고, EC2는 **SSH 역방향 터널**로 접속합니다.
터널이 연결되면 EC2 안에서 `http://127.0.0.1:18788` 로 요청하면 됩니다. (EC2 쪽 18788 → 강의실 PC 8788)

## 인증
모든 POST 요청 헤더에 `X-Quiz-Token: <토큰>` 을 넣습니다. 토큰은 강의실 PC의 `token.txt` 값이며,
채팅이 아니라 직접 전달하고 EC2 환경 변수(예: `QUIZ_TOKEN`)에만 저장합니다.

## GET /health
서버 상태 확인. 인증 필요 없음.
```json
{"ok": true, "model": "qwen3:14b", "reviewer": "qwen3:14b", "busy": false, "topics": 1054}
```
`busy: true` 면 다른 요청을 처리 중이라 이번 요청은 기다리게 됩니다.

## POST /quiz
유저가 학습을 시작할 때 호출합니다. 문제를 새로 만들어 돌려줍니다 (보통 1~2분, 다른 요청이 처리 중이면 더 걸림).
```json
요청: {"topicId": "ds-01", "count": 4}
응답: {
  "topicId": "ds-01",
  "questions": [
    {"type": "mc", "q": "…은?", "choices": ["…","…","…","…"], "answer": 1, "explain": "…입니다.", "source": "live"},
    {"type": "ox", "q": "…다.", "answer": false, "explain": "…입니다.", "source": "pool"}
  ],
  "model": "qwen3:14b", "generated": 3, "seconds": 84
}
```
- 문제 형식은 앱 문제 은행과 같습니다 (`mc`: 보기 4개 + 정답 번호 0~3, `ox`: 정답 true=O / false=X).
- `source`: `live` = 이번에 새로 만든 문제, `pool` = 새 문제가 모자라서 미리 만든 문제로 채운 것.
- 새 문제도 미리 만든 문제도 없으면 `questions` 가 빈 배열일 수 있습니다 → 팀 문제 은행으로 대신합니다.
- 오류: 400 (topicId·count 잘못됨), 401 (토큰 틀림), 404 (없는 주소).

## EC2 쪽 권장 처리 (김창원)
1. 학습 시작 시 POST /quiz 를 **비동기로** 호출 (15분 학습 동안 기다림). 시간 제한은 10분 정도.
2. 연결 실패·시간 초과·빈 응답이면 DB `ai_quizzes` 의 미리 만든 문제를 씀.
3. 받은 문제는 DB에도 저장해 두면 다음에 창고로 쓸 수 있음.
4. 학습이 끝나면 AI 문제 4개 + 팀 문제 은행 3개를 섞어서 냄.

## 터널 (참고)
강의실 PC에서: `ssh -N -R 127.0.0.1:18788:127.0.0.1:8788 -i <키 파일> <터널 사용자>@<EC2 주소>` (tunnel.py 가 자동 재연결)
EC2에는 터널 전용 사용자(쉘 없음, 포트 연결만 허용)와, 학교 IP에서 오는 SSH만 허용하는 보안 그룹이 필요합니다.
