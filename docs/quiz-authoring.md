# 퀴즈 문제 작성 기준

앱에 내장하는 문제 은행(`app/src/data/quizbank/*.json`)을 만들 때 지키는 기준입니다.
사람이 쓰든 AI가 초안을 쓰든 같은 기준으로 작성하고, 출시 전에는 해당 분야를 아는 팀원이 검토합니다.

## 분량
- 주제 1개당 **15문제**: 4지선다(`mc`) **11개** + OX(`ox`) **4개**
- 앱은 풀 때마다 이 중 10문제(4지선다 7 + OX 3)를 골라 보기 순서를 섞어 냅니다.

## 내용
- 모든 문제는 **그 주제 하나**에 대한 것입니다. 다음을 고르게 섞습니다.
  - 정의·핵심 특징
  - 동작 원리·작동 방식·과정의 순서
  - 장단점, 쓰이는 곳
  - 비슷한 개념과의 차이 (예: 대칭키 vs 공개키, IDS vs IPS)
  - 적용 사례·상황 판단 ("이런 상황에서 알맞은 것은?")
  - Lv.3 주제는 간단한 계산·분석 문제를 1~3개 넣어도 됩니다.
- 교과서·위키백과 수준에서 **널리 인정되는 사실만** 씁니다.
  출처마다 다를 수 있는 수치, 연도·인명 암기, 특정 제품 버전 같은 문제는 피합니다.
- 난이도는 주제의 Lv에 맞춥니다.
  - Lv.1 기초: 정의, 핵심 특징, 대표 예시
  - Lv.2 중급: 원리, 비교, 적용
  - Lv.3 심화: 응용, 분석, 계산, 한계
- 정답은 **하나로 분명**해야 합니다. "모두 맞다", "정답 없음", "위 보기 모두" 같은 보기는 쓰지 않습니다.
- 4지선다 오답은 **그럴듯하지만 분명히 틀린** 내용으로 만들고, 정답 위치(0~3)를 고르게 섞습니다.
- OX는 맞는 진술(true)과 틀린 진술(false)을 섞습니다 (4개 중 2:2 또는 3:1).
- 문제·해설은 자연스러운 한국어로 씁니다. 전공 용어는 한국어로 쓰고 필요하면 괄호에 영어를 덧붙입니다.
- `explain`에는 **왜** 그것이 정답인지 1~2문장으로 씁니다 (틀린 사람이 읽고 배울 수 있게).
- 길이: 문제·해설 각 400자 이하, 보기 각 200자 이하. 휴대폰 화면에서 읽기 쉽게 짧게 씁니다.

## 파일 형식
```json
{
  "sec-01": [
    { "type": "mc", "q": "정보보안의 3요소(CIA)에 해당하지 않는 것은?", "choices": ["기밀성", "무결성", "가용성", "익명성"], "answer": 3, "explain": "CIA는 기밀성(Confidentiality), 무결성(Integrity), 가용성(Availability)입니다." },
    { "type": "ox", "q": "무결성은 허가받지 않은 사람이 정보를 볼 수 없게 하는 성질이다.", "answer": false, "explain": "그것은 기밀성입니다. 무결성은 정보가 허가 없이 바뀌지 않는 성질입니다." }
  ]
}
```
- 키는 주제 id (`api/supabase/functions/generate-quiz/topics.json`에 있는 id)
- `mc`: `choices` 4개, `answer`는 정답 보기 번호(0부터)
- `ox`: `answer`는 `true`(O) / `false`(X), `choices` 없음
- UTF-8, 올바른 JSON (마지막 쉼표 금지)
